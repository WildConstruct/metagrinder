# Meat Grinder Artifact Contract v1

_Last updated: 2026-03-07_

## 1. Purpose

This document defines the v1 artifacts emitted by the Metagrinder.

The goal is to keep outputs bounded and interoperable.

The contract covers:

1. user research package
2. staged UTDG contribution package
3. canonical UTDG record shape

### Naming

Informal product language:

- the Metagrinder makes `metaballs`
- a `metaball` is a PSG project or packaged PSG output generated by the Metagrinder

Contract rule:

- `metaball` is a product nickname, not a schema term
- manifest and file formats should continue to use explicit names like `research-package` and `utdg-submission`

## 2. Design Rules

1. One parse may emit multiple artifacts.
2. User package and UTDG package are separate but linked.
3. Canonical UTDG is not emitted directly by the parser.
4. Every artifact needs stable IDs, provenance, and review metadata.

## 3. Artifact Set

### A. User research package

Primary purpose:

- support the user's own project work

Files:

- `source-map.psg`
- `claims-and-evidence.psg`
- `concept-clusters.psg`
- `prompt-synthesis.psg`
- `prompt-mutations.psg`
- `research-package.json`

### B. UTDG contribution package

Primary purpose:

- submit candidate shared knowledge into staging

Files:

- `utdg-candidates.json`
- `utdg-evidence.psg`
- `utdg-submission.json`

### C. Canonical UTDG record set

Primary purpose:

- represent approved shared records

Storage target:

- canonical UTDG service or datastore

## 4. Shared Metadata Envelope

All package manifests should include:

- `packageId`
- `packageType`
- `createdAt`
- `parserVersion`
- `strategyVersion`
- `sourceInputIds`
- `contributorId`
- `confidenceSummary`
- `reviewStatus`

## 5. User Research Package Contract

### 5.1 `research-package.json`

Required fields:

- `packageId`
- `packageType`: `research-package`
- `title`
- `sourceInputs[]`
- `collections[]`
- `lineage`
- `confidenceSummary`
- `reviewStatus`

Suggested shape:

```json
{
  "packageId": "rpkg_001",
  "packageType": "research-package",
  "title": "Late Medieval Textile Research Package",
  "sourceInputs": ["src_1"],
  "collections": [
    { "id": "col_source", "type": "source-map", "path": "source-map.psg" },
    { "id": "col_claims", "type": "claims-and-evidence", "path": "claims-and-evidence.psg" },
    { "id": "col_concepts", "type": "concept-clusters", "path": "concept-clusters.psg" },
    { "id": "col_synthesis", "type": "prompt-synthesis", "path": "prompt-synthesis.psg" },
    { "id": "col_mutations", "type": "prompt-mutations", "path": "prompt-mutations.psg" }
  ],
  "lineage": {
    "sourceInputIds": ["src_1"]
  },
  "confidenceSummary": {
    "overall": "medium"
  },
  "reviewStatus": "draft"
}
```

### 5.2 PSG collection requirements

Each PSG file should include metadata fields for:

- `packageId`
- `collectionType`
- `sourceInputIds`
- `utdgRefs[]` where relevant
- `lineage`

### 5.3 Collection types

Allowed v1 collection types:

- `source-map`
- `claims-and-evidence`
- `concept-clusters`
- `prompt-synthesis`
- `prompt-mutations`

## 6. UTDG Contribution Package Contract

### 6.1 `utdg-submission.json`

Required fields:

- `submissionId`
- `packageType`: `utdg-submission`
- `derivedFromPackageId`
- `candidateFile`
- `evidenceFile`
- `contributorId`
- `submissionMode`
- `reviewStatus`

Suggested shape:

```json
{
  "submissionId": "usub_001",
  "packageType": "utdg-submission",
  "derivedFromPackageId": "rpkg_001",
  "candidateFile": "utdg-candidates.json",
  "evidenceFile": "utdg-evidence.psg",
  "contributorId": "user_123",
  "submissionMode": "staged",
  "reviewStatus": "staged"
}
```

### 6.2 `utdg-candidates.json`

Required fields:

- `submissionId`
- `derivedFromPackageId`
- `candidates[]`

Each candidate requires:

- `candidateId`
- `entityType`
- `label`
- `summary`
- `sourceRefs[]`
- `evidenceRefs[]`
- `proposedRightsProfile`
- `sourceRights`
- `contributionTerms`
- `rightsConfidence`
- `commercialAllowed`
- `normalization`
- `confidence`
- `reviewStatus`

Suggested candidate shape:

```json
{
  "candidateId": "cand_001",
  "entityType": "Archetype",
  "label": "coarse homespun linen",
  "summary": "A rough linen archetype associated with lower-status garments.",
  "sourceRefs": ["src_rec_1"],
  "evidenceRefs": ["ev_1"],
  "proposedRightsProfile": "reference-only",
  "sourceRights": "Institution Terms",
  "contributionTerms": "platform-community-commons",
  "rightsConfidence": "medium",
  "commercialAllowed": false,
  "normalization": {
    "conceptType": "material",
    "externalIds": {
      "gettyAatId": null
    }
  },
  "confidence": {
    "extraction": "medium",
    "normalization": "medium"
  },
  "reviewStatus": "staged"
}
```

### 6.3 `utdg-evidence.psg`

Purpose:

- let users and curators inspect evidence and provenance visually

Recommended node families:

- `SourceChunk`
- `Evidence`
- `Candidate`
- `SourceCitation`
- `OpenQuestion`

## 7. Canonical UTDG Record Contract

Canonical records are created only after review.

### 7.1 Required fields

- `id`
- `entityType`
- `label`
- `summary` or `definition`
- `externalIds`
- `provenanceRefs`
- `evidenceRefs`
- `rightsProfile`
- `sourceRights`
- `contributionTerms`
- `rightsConfidence`
- `commercialAllowed`
- `reviewStatus`
- `createdFromSubmissionId`

### 7.2 Canonical record shape

```json
{
  "id": "utdg:archetype:coarse-homespun-linen",
  "entityType": "Archetype",
  "label": "coarse homespun linen",
  "summary": "A rough linen archetype associated with low-status garment contexts.",
  "externalIds": {
    "gettyAatId": null
  },
  "provenanceRefs": ["utdg:evidence:ev_1"],
  "evidenceRefs": ["utdg:evidence:ev_1"],
  "rightsProfile": "reference-only",
  "sourceRights": "Institution Terms",
  "contributionTerms": "platform-community-commons",
  "rightsConfidence": "medium",
  "commercialAllowed": false,
  "reviewStatus": "approved",
  "createdFromSubmissionId": "usub_001"
}
```

## 8. ID Rules

### Package IDs

- `rpkg_*` for research packages
- `usub_*` for UTDG submissions

### Candidate IDs

- `cand_*`

### Canonical IDs

- `utdg:concept:*`
- `utdg:archetype:*`
- `utdg:evidence:*`
- `utdg:rule:*`

## 9. Review Rules

### User research package

Can remain:

- `draft`
- `private`
- `team`

### UTDG contribution package

Can move through:

- `draft`
- `staged`
- `needs_review`
- `approved`
- `merged`
- `rejected`
- `restricted`

### Canonical UTDG records

Should only exist with:

- `approved`
- `merged`
- `restricted`

## 10. Validation Rules

### All packages

Must validate:

- required metadata envelope
- stable IDs
- source references present

### UTDG submission packages

Must validate:

- rights fields present
- candidate types valid
- provenance present
- derived package ID present

### Canonical records

Must validate:

- rights profile present
- source rights present
- contribution terms present
- rights confidence present
- provenance refs present
- review state valid

## 11. Deliberate Non-Goals For v1

- full binary packaging format
- nested package standards
- complete cross-package dependency graph
- automatic direct publish

## 12. Recommendation

Use this as the minimum artifact contract for prototyping.

If the system stays inside these boundaries, it will be easier to:

- test
- review
- stage
- evolve without schema sprawl
