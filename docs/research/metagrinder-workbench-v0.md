# Metagrinder Workbench v0

Metagrinder Workbench is a local, file-backed artifact dashboard for reviewing an existing Metagrinder output folder. It is intentionally narrower than a product shell: no database, auth, cloud sync, page scraping, live retrieval controls, or backend extraction changes.

## Run

```bash
node packages/core/scripts/serve-metagrinder-workbench.js --port 5174
```

Then open:

```txt
http://127.0.0.1:5174
```

The root package script is:

```bash
pnpm run:metagrinder-workbench
```

In the current synced Windows workspace, pnpm dependency materialization may still fail. The direct `node` command uses only Node built-ins.

## Scope

The Workbench opens a Metagrinder output folder, reads `research-package.json`, lists package collections, and displays common review artifacts:

- `scene-grammar.json`
- `accepted-scene-grammar.json`
- `retrieval-candidates.json`
- `candidate-inspection.json`
- `source-evidence.json`
- `source-claims.json`
- `grammar-revisions.json`
- `accepted-grammar-deltas.json`
- `psg-compile-diff.json`
- `scene-grammar.psg`
- `branch-graphs/*.psg`

## Write Boundary

Workbench v0 may write only these operator state files:

- `source-intake-approval.json`
- `source-claim-review.json`
- `revision-state.json`
- `retrieval-policy.json`

It must not directly mutate generated artifacts such as `accepted-scene-grammar.json`, `accepted-grammar-deltas.json`, `source-claims.json`, or PSG files. The rerun action invokes the existing Metagrinder pipeline and passes state files back through the established review path.

## Safety Invariants

- Live retrieval remains outside this UI.
- Candidates remain candidate-only until approved by `source-intake-approval.json`.
- Source claims remain citation-gated by `source-claim-review.json`.
- Accepted grammar changes only through accepted, citation-gated revisions.
- PSG output remains generated by the existing compiler.

## Pasted Article Runs

Run Setup supports pasting a deep research article directly into the browser. Workbench writes the pasted text to a new timestamped local run folder under `tmp/metagrinder-workbench-runs/<slug>-<timestamp>/source-input.txt`, invokes the existing Metagrinder pipeline, and then opens the generated output folder.

The paste flow does not add live retrieval, page scraping, automatic source-claim creation, or direct grammar mutation. It only creates a local input text file and lets the established pipeline produce artifacts.

## Theme

Workbench defaults to dark mode. The header toggle switches between dark and light mode and stores the choice in `localStorage`.

## Recent Runs And Codex Reuse

Run Setup lists recent local runs from `tmp/metagrinder-workbench-runs`. Opening a recent run reads the existing `research-package.json` and does not rerun Metagrinder or Codex.

If a run already has `codex-parse-result.json`, the Semantic Parse screen reuses it by default and rebuilds downstream artifacts from the existing result. A force rerun is available only under an advanced section because it spends a new Codex parse.

## PSG Export Shape

Semantic scene grammar PSG output is compiled as a linear branch sequence: brief subject, age/sex, role/type, hat or hair, upper body, lower body, footwear, accessories, condition/behavior, compose, and output. Fully partitioned conditional subgraphs remain deferred.
